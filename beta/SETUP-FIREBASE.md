# Общий доступ по почте — настройка (один раз, ~5 минут)

Приложение статическое, своего сервера у него нет. Чтобы жена заходила по своей
почте и видела те же данные, нужен бесплатный проект Firebase: он проверяет, кто
вошёл, и хранит бюджет так, чтобы его видели только разрешённые почты.

Всё, что ниже, делается один раз твоим Google-аккаунтом.

---

## 1. Создать проект

1. Открыть <https://console.firebase.google.com/> → **Add project**
2. Имя — например `budget-kg`. Google Analytics **выключить** (не нужен).
3. Дождаться создания → **Continue**.

## 2. Включить вход по ссылке из письма

1. Слева **Build → Authentication** → **Get started**
2. Вкладка **Sign-in method** → в списке выбрать **Email/Password**
3. Внутри включить **оба** тумблера:
   - **Email/Password** — Enable
   - **Email link (passwordless sign-in)** — Enable
4. **Save**

## 3. Разрешить домен приложения

1. Authentication → вкладка **Settings** → **Authorized domains**
2. **Add domain** → `kg881.github.io` → Add

Без этого шага письмо не отправится: браузер вернёт `auth/unauthorized-domain`.

## 4. Создать базу

1. Слева **Build → Firestore Database** → **Create database**
2. Режим — **Start in production mode** (правила всё равно заменим на свои)
3. Регион — **eur3 (europe-west)** или любой европейский → **Enable**

## 5. Вставить правила доступа

1. Firestore Database → вкладка **Rules**
2. Стереть всё, вставить содержимое файла `beta/firestore.rules` из этого
   репозитория целиком
3. **Publish**

Эти правила — единственное, что закрывает данные. Смысл: документы хозяйства
читает и пишет только тот, чья почта есть в списке участников; список участников
меняет только владелец. Проверяет сервер, из браузера обойти нельзя.

## 6. Забрать конфиг и вставить в приложение

1. Шестерёнка сверху слева → **Project settings** → блок **Your apps**
2. Нажать иконку **`</>`** (Web) → App nickname `budget` → **Register app**
   (галочку про Firebase Hosting **не** ставить)
3. Показанный объект `firebaseConfig` скопировать целиком
4. Открыть <https://kg881.github.io/budget/beta/> → раскрыть **Настройки** →
   блок **Общий доступ по почте** → вставить конфиг → **Сохранить конфиг**

Страница перезагрузится. Конфиг публичный, его не страшно держать в браузере и в
коде — доступ к данным закрывают правила из шага 5, а не он.

## 7. Войти и добавить жену

1. В том же блоке ввести свою почту → **Прислать ссылку для входа**
2. Открыть ссылку из письма **на этом же устройстве** → ты вошёл как владелец,
   твои данные уезжают в облако
3. Появится поле **Добавить почту** → ввести почту жены → **Дать доступ**
4. Жена открывает <https://kg881.github.io/budget/beta/>, вводит свою почту,
   жмёт кнопку и заходит по ссылке из письма

Дальше она пользуется приложением полноценно: видит все месяцы, вносит свои
категории, правит цели и бонусы. Изменения появляются у обоих сразу.

---

## Как устроено хранение

| Что | Где лежит |
|---|---|
| настройки, шаблон, правки бонусов | `households/{id}` — один документ |
| каждый месяц | `households/{id}/months/{2026-06}` — отдельный документ |
| цели, бонусы, счета, конверты, история | `households/{id}/lists/{имя}` |
| какая почта в каком хозяйстве | `invites/{почта}` |

Месяцы лежат раздельно намеренно: пока ты правишь август, а жена сентябрь, вы не
затираете друг друга. Столкнуться можно только внутри одного и того же месяца —
там побеждает та правка, что сохранилась последней.

## Что с данными до входа

Пока не вошёл — приложение работает как раньше, данные только в браузере.
При первом входе:

- **облако пустое** → туда заливается то, что есть на устройстве;
- **облако с данными, устройство пустое** → данные забираются из облака;
- **и там, и там что-то есть** → приложение спрашивает, что взять за основу, и
  перед тем как принять облачную версию, кладёт снимок локальной в
  `localStorage` под ключ `budget-cloud-snapshot-precloud`. Вернуть его можно
  кнопкой **«Вернуть копию до подключения облака»** в том же блоке настроек.

## Лимиты бесплатного тарифа

Spark (бесплатный): 50 000 чтений и 20 000 записей в день, 1 ГиБ хранилища.
Бюджет на двоих — это десятки операций в день. Карта не нужна.

## Если что-то пошло не так

| Симптом | Причина |
|---|---|
| `auth/unauthorized-domain` | не сделан шаг 3 |
| `auth/operation-not-allowed` | не включён Email link в шаге 2 |
| чип «нет доступа» | правила не опубликованы (шаг 5) или почта не в списке участников |
| письмо не приходит | проверить спам; отправитель — `noreply@<проект>.firebaseapp.com` |
